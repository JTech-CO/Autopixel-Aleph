# AutoPixel-ℵ 2.2.0

이번 수정본은 **2.2.0 (overlay fix 1)**입니다. Wplace 새 빌드의 공식 도안 연결을 지원합니다. ZIP을 다시 받아 확장을 갱신하고 게임 탭도 새로고침하세요.
[English](README.md) | 한국어

## 업데이트

현재 버전은 autopixel-aleph 폴더입니다.

1. ZIP을 새 폴더에 풀고 Chrome 확장 관리에서 그 폴더를 로드합니다. 기존 폴더를 갱신했다면 확장을 새로고침합니다.
2. 버전 **2.2.0**를 확인하고 **Wplace 탭도 새로고침**합니다. 두 버전을 동시에 켜지 마세요.
3. 공식 도안을 열고 보정 → 구획 선택 → **오버레이 (i)** → **공식 자동** → 시작합니다.

## 공식 도안을 그대로 사용

PNG 재첨부, PNG 크기 입력, 도안 좌상단 지정이 필요 없습니다. 게임에서 드래그로 배치한 공식 도안의 좌표·변환된 색·투명도를 읽습니다.

- **지도:** 공식 도안의 빌드 화면을 열어 둡니다. 실행 중 공식 ‘잘못된 픽셀 표시’를 잠시 켜서 게임의 비교 결과를 읽고 종료 시 복원합니다. 도안을 숨기거나 화면을 캡처할 필요가 없습니다.
- **Alliance Pixel editor / HQ:** 공식 도안 렌더러의 원본 픽셀과 실제 바탕 캔버스를 비교합니다. 도안의 표시 방식·불투명도와 별개로 원본을 읽습니다. 확장 업데이트 전에 열린 도안의 데이터가 없으면 닫았다 다시 열라는 안내가 나옵니다.
- 투명 칸과 도안 범위 밖은 칠하지 않습니다. ‘정확한 색상 건너뛰기’가 켜져 있으면 이미 맞는 칸도 건너뜁니다.
- 색이나 바탕 데이터가 준비되지 않으면 미확인 칸을 칠하지 않고 사유를 표시합니다.
- **현재색**은 선택된 색으로 칠하는 모드로, 공식 도안의 자동 비교는 적용하지 않습니다.

## 정확도를 우선하는 입력

i를 두 번 눌러 피커를 켠 뒤 첫 클릭으로 색을 추출합니다. 피커가 해제되고 선택된 색이 현재 도안의 정확한 색과 일치하는 것을 확인한 후에만 칠하기 클릭을 보냅니다. 이전 칸과 같은 색이어도 새로운 피커 동작 완료를 기다립니다.

단순히 i를 두 번 누른 결과가 같다고 ‘이미 맞는 색’으로 판단하지 않습니다. 동일 색·투명 칸은 도안 데이터와 실제 픽셀 상태로 구분합니다.

안전 **10**, 빠름 **20**, 터보 **30px/s**는 상한입니다. 화면 갱신이나 색 추출이 늦으면 기다리므로 실제 속도는 낮아집니다. 늦어진 시간을 보충하려고 칠하기 클릭을 몰아서 보내지 않습니다. 완료된 색 추출의 색이 어긋나면 같은 칸에서 최대 3회 확인합니다. 계속 어긋나는 칸은 미도색으로 남기고 다음 칸을 진행합니다. 아직 응답이 없는 추출은 겹쳐 실행하지 않습니다. 응답이 뒤늦게 도착하면 다시 시작할 수 있으며, 응답이 계속 없을 때만 게임 탭을 새로고침하세요.

## 모양과 조작

사각형·타원·자유곡선과 새로 선택·추가·빼기를 조합해 구멍이나 떨어진 영역을 만들 수 있습니다. 자유곡선은 마우스를 놓으면 닫힙니다. 시작/정지 버튼은 설정을 스크롤해도 보입니다. 사용자가 지도에 입력하거나 탭이 숨겨지면 기존 보호 기능에 따라 일시정지합니다.

## 수동 호환 모드

‘PNG 비교’와 ‘분리 캔버스’는 기존 도구 호환용입니다. 이 모드만 PNG와 실제 캔버스 지정이 필요합니다. PNG 비교는 공식 도안을 숨기고 실제 그림을 한 번 읽은 후 도안을 다시 표시해야 합니다. 지도 이동·그림 변경 후에는 다시 읽습니다. 공식 도안에는 기본 ‘공식 자동’을 권장합니다.

## 검증 범위

공개 Wplace 코드의 피커·팔레트·지도·Alliance 렌더러 경로를 확인하고, 로컬 브라우저에서 지연 응답·1,000칸 색 전환·투명/완성 칸 건너뛰기·중단·속도 상한을 검증했습니다. 실제 로그인 계정의 서버 저장 성공률이나 실게임 오류율을 측정한 결과는 아닙니다.

자동 비교는 게임이 현재 로드한 상태를 기준으로 합니다. 다른 사용자의 변경이 아직 반영되지 않았다면 서버의 최신 상태와 다를 수 있습니다. 공식 사이트의 내부 구조가 바뀌면 해당 어댑터 업데이트가 필요하며, 지원하지 않는 상태에서는 칠하지 않습니다. 상세 결과와 코드 근거는 CHANGES.md 및 tests/에 있습니다.
